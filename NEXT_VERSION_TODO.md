# NEXT_VERSION_TODO

Ідеї для версій після V1. Наведене нижче **не є чинними правилами V1**. У V1, коли при Camp-bound атаці Castle Region захисник не має legal Retreat, лише Army, повністю розміщені «у замку» з effective threshold 0, виходять із бою без втрат; решта б'ються з примусовим порогом 100% і при поразці повністю знищуються.

## 1. Укриття в Castle, коли немає напрямку Retreat

Мета: замінити спрощення V1 механікою, за якої після поразки без доступного сусіднього Retreat уцілілі захисники можуть укритися в Castle за умови достатньої місткості Barracks.

Застосування: **Camp-bound атака на Castle Region**, коли захисник не має legal Retreat до сусідньої Region. Для Transit-атаки Castle Region діють звичайні пороги втрат і pre-battle Retreat; переміщення в Castle після поразки не вимагається.

Попередній алгоритм (виконується на Battle Start перед combat calculation):

1. Для перевірки місткості умовно вважати, що всі Army, які **не** мають effective Defense Loss Threshold 0 (включно з pre-battle Retreat), вийшли із Castle. Враховувати зайнятість Barracks іншими військами та Reserve Soldier.
2. Перевірити, чи вистачить місць у Castle для **всіх** Army з effective threshold 0 / pre-battle Retreat. Якщо вистачить — усі вони достроково виходять із бойового розрахунку без втрат; у випадку Occupation розміщуються «у замку».
3. Якщо місць для всіх таких Army недостатньо — достроково виходять без втрат **лише Army, які вже повністю розміщені «у замку»** та мають effective threshold 0 / pre-battle Retreat. Army з threshold 0, що не повністю перебувають у Castle, залишаються в бойовому розрахунку.
4. Для всіх Army, що залишилися в бою, скасувати pre-battle Retreat.
5. Розрахувати `Th1` — мінімальний відсоток втрат, за якого **всі Soldier, що виживуть у бою**, зможуть розміститися в Castle, з урахуванням місць, зайнятих Army, які достроково вийшли з бою, та іншими мешканцями Barracks.
6. Розрахувати `Th2` — мінімальний ненульовий поріг втрат серед Army, що залишилися в бою. Якщо в усіх цих Army поріг дорівнює 0, прийняти `Th2 = 0`.
7. Спільний поріг втрат захисника: `Th = max(Th1, Th2)`. У цьому розрахунку не враховувати поточний режим «у замку» / «поза замком» Army, що беруть участь у бою.
8. Якщо захисник програв і Camp-bound Attacker створив Occupation, розмістити в Castle Army, які достроково вийшли з бою, та вцілілих учасників бою; вони стають `BlockedInCastle`. Якщо захисник виграв, режими розміщення всіх Unit залишаються без змін.

**Питання до проєктування перед реалізацією:** точно визначити, як обчислювати `Th1` з урахуванням округлення та фактичного розподілу casualties, щоб гарантовано не перевищити Barracks Capacity; як рахувати Knight без Soldier; що робити при недостатній місткості для Knight/Unit, а також перевірити випадки, коли бойових учасників не залишилося. Алгоритм вище — зафіксований задум, а не остаточна технічна специфікація.

## 2. Економіка заблокованого Castle

**Уточнити споживання та виробництво Coins заблокованим Castle.** Окремо визначити, які власні будівлі продовжують генерувати Coins, як списуються витрати Castle та upkeep військ/населення під час Occupation і як це співвідноситься з глобальним балансом Coins Player.
