# Феодали — UI/UX ТЗ для першої тестової версії

## 0. Статус документа

Це робоче ТЗ по UI першої тестової версії.

**Важливо:** механізм отримання, підписки та оновлення ігрової інформації між frontend і backend поки **не вирішений остаточно**. UI не повинен залежати від конкретного транспорту. Компоненти мають працювати однаково незалежно від того, чи актуальний стан надходить через WebSocket, HTTP API або комбінований механізм.

Backend є authoritative source стану гри.

## 1. Загальні принципи

Головний екран гри — карта.

На desktop детальні сутності відкриваються переважно як вікна/панелі поверх карти. На mobile ті самі сутності відкриваються переважно як окремі екрани. Надалі слово «вікно» означає обидва варіанти.

Mobile підтримується з першої версії. Hover не може бути єдиним способом отримати інформацію або виконати дію.

Одна й та сама сутність повинна мати одне універсальне детальне вікно незалежно від того, звідки воно відкрите: лицар, армія/загін, замок, область.

Недоступні дії:
- якщо дія принципово не має сенсу в поточному контексті — не показувати;
- якщо дія потенційно корисна, але зараз не виконані умови — можна показати disabled з короткою причиною;
- disabled-дії показувати лише тоді, коли ця інформація реально допомагає гравцю.

## 2. Постійно видимий глобальний UI

На всіх основних екранах доступні:
- монети;
- золото;
- срібло;
- «Замки»;
- «Лицарі»;
- «Армії»;
- «Сповіщення»;
- «Мітки»;
- «Обстановка»;
- блок оперативних повідомлень;
- toast-повідомлення.

«Сповіщення» має індикатор непрочитаних.

«Обстановка» може підсвічуватися різними рівнями інтенсивності залежно від близькості чужих військ.

## 3. Карта

### 3.1. Загальне

Світ поділений на hex-області.

Координати, видимі гравцю: `(q, r)`.

Передбачити кілька scale-рівнів. На дрібному масштабі частина деталей та іконок приховується.

### 3.2. Політичний статус

Базовий колір області:
- моя;
- союзна — зарезервувати колір;
- нейтральна;
- чужа.

Окупація позначається штрихуванням:
- червоне — моя область окупована ворогом;
- зелене — чужа область окупована мною;
- сіре — чужа область окупована третім гравцем.

Між сусідніми областями різних власників показувати кордон.

### 3.3. Місцевість і ресурси

На області показуються умовні елементи ландшафту: ліси, поля, гори, пустелі тощо, щоб без відкриття деталей можна було приблизно оцінити ресурсний профіль.

Точні іконки, кольори, щільність графіки та scale-режими визначити при реалізації.

### 3.4. Міста

Місто позначається окремою іконкою.

### 3.5. Війська на карті

Іконки показують не кожну Army окремо, а факт наявності військ певного типу/стану.

Приклад:
- Camp — іконка табору;
- свої — зелений/власний колір;
- чужі — червоний/ворожий;
- якщо присутні обидві сторони — дві сусідні іконки або комбінована.

Для руху:
- першу половину `transit_time` чужої Army показується сторона входу і рух у напрямку центру;
- після `0.5 * transit_time` стає відомо, через яку грань Army вийде, і UI показує напрямок виходу;
- для руху до Camp після моменту розкриття показується ознака майбутньої зупинки;
- для виходу з Camp показується відповідна ознака і напрямок.

### 3.6. Hover / tap

Desktop: hover показує компактну інформацію.

Mobile: аналогічна інформація доступна через tap/вибір області.

Коротка картка може містити:
- координати;
- статус/власника;
- джерела ресурсів;
- місто;
- коротку інформацію про війська.

Клік/тап відкриває повне вікно області.

## 4. Меню «Замки»

Список усіх замків гравця з короткою зведеною інформацією.

Конкретний набір другорядних полів визначити в UI, але бажано показувати:
- назву;
- запаси;
- короткий баланс їжі/монет;
- активні процеси;
- проблемні стани;
- кількість лицарів/військ.

Клік по назві відкриває першу вкладку замку.

Передбачити прямі переходи з рядка замку до конкретних вкладок.

## 5. Вікно замку

### 5.1. Шапка

Показує:
- назву;
- перейменування;
- кнопку переходу/центрування на карті;
- дерево, камінь, залізо, їжу;
- індикатори заповнення Warehouse/Granary;
- при повному сховищі індикатор червоний;
- за можливості компактний поточний баланс їжі та монет.

### 5.2. Вкладка «Будівлі»

Список будівель.

Рекомендована структура:
- зліва: назва, рівень, їжа, монети;
- по центру: функціональний блок;
- справа: вартість покращення, кнопка, таймер.

Сортування:
1. будівлі, які зараз покращуються;
2. побудовані;
3. рівня 0 — сірим у кінці.

Для рівня 0:
- назва;
- короткий опис;
- умови;
- вартість;
- «Побудувати».

Функціональна інформація:
- Palace: кількість лицарів, прогрес появи нового замість загиблого;
- Warehouse: місткість, % заповнення по кожному bulk-resource, прогноз часу до заповнення;
- Granary: місткість, % заповнення, час до заповнення/спорожнення;
- Bank: multiplier;
- Barracks: місткість, зайнятість, recruitment queue;
- інші — відповідно до функції.

Клік по будівлі відкриває детальну інформацію про рівні та майбутні додаткові функції.

### 5.3. Вкладка «Ресурси»

Показує:
- виробництво;
- споживання;
- доставку;
- чистий баланс;
- втрати ефективності через відстань;
- місто, якщо є.

Нижче — області замку, відсортовані за відстанню.

Формат accordion:
- постійно видно дохід/витрати з урахуванням доставки та місто;
- у розгорнутому стані: джерела, їх рівні, upgrade cost, кнопки upgrade, активні таймери.

### 5.4. Вкладка «Солдати й лицарі»

Одна вкладка для обліку, набору солдатів і лицарів.

Верхня частина — зведені блоки.

#### Всього солдатів

Показувати:
- загальну кількість солдатів замку по типах;
- у казармі: `N / capacity`;
- загальне утримання в їжі;
- загальне утримання в монетах;
- «Деталі» — розгортає деталізацію утримання за статусами.

#### Резерв

Показувати:
- резерв по типах;
- `Готується: N`;
- «Набір» — розгортає recruitment UI.

Резерв = солдати в казармі, не закріплені за жодним лицарем.

#### Лицарі

Один список усіх лицарів цього замку.

Сортування:
1. ті, хто зараз фізично в області замку;
2. решта.

Не ділити на окремі секції «в замку / поза замком».

Для лицаря:
- `Сір {ім'я}`;
- шаблон належності: `Сір Ренар з [іконка замку] Альденбург`;
- англійською: `Sir Renard of [castle icon] Aldenburg`;
- досвід;
- стан;
- місцезнаходження;
- склад загону;
- роль у Army:
  - `В підпорядкуванні Сіра ...`;
  - `Головнокомандувач армії`;
  - нічого, якщо це окремий загін.

Якщо лицар фізично в області замку:
- можна додавати/знімати солдатів;
- можна керувати станом солдатів «у казармі / не в казармі», якщо це дозволено правилами;
- входження лицаря до багатозагонової Army не блокує зміну складу його загону.

Список лицарів має власний scroll. Верхні блоки зі статистикою можуть бути стабільними/компактними.

### 5.5. Вкладка «Армії та загони»

Короткий опис:
`Інформація про армії та загони, які зараз знаходяться на території замку.`

Показуються всі Army/загони, фізично присутні в області замку, включно з військами інших замків і військами в русі через область.

UI:
- backend Army з одним Knight показується як «загін»;
- Army з кількома Knight/Units — як «армія».

Для рядка:
- командувач;
- його домашній замок;
- досвід;
- кількість лицарів;
- кількість солдатів;
- бойова сила;
- стан;
- маршрут/напрямок;
- ETA;
- утримання;
- пороги втрат.

«Детальніше»:
- повний список лицарів;
- склад кожного загону.

«Переформування»:
- виділити частину загонів у нову Army;
- повністю розформувати Army на окремі загони;
- змінити Commander-in-Chief;
- змінити пороги втрат.

Для одиночного загону недоречні функції не показувати.

Біля рядків — checkbox.

При виборі кількох сумісних Army/загонів:
- «Об'єднати»;
- окреме вікно з вибором головнокомандувача і нових порогів.

### 5.6. Можливі додаткові вкладки

Пізніше можуть бути:
- «Статистика»;
- «Території»;
- «Територія».

Не фіксувати остаточно до завершення дизайну вікна області і повного керування військами.

## 6. Меню «Лицарі»

Глобальний список усіх лицарів гравця.

Це глобальний огляд, а не окремий центр керування.

Показувати:
- ім'я;
- домашній замок;
- досвід;
- стан;
- місцезнаходження;
- склад загону;
- роль у Army;
- переходи до лицаря, Army/загону, замку.

## 7. Вікно лицаря

Однакове незалежно від джерела відкриття.

Показує:
- ім'я;
- домашній замок;
- досвід;
- стан;
- місцезнаходження;
- склад загону;
- утримання;
- роль у Army;
- бойову/ключову статистику, якщо вона ведеться;
- доступні дії залежно від стану.

Передбачити окремий перехід до самого лицаря і до його загону в контексті Army.

## 8. Меню «Армії»

Глобальний список усіх власних Army та одиночних загонів.

Акцент:
- стан;
- рух;
- бойові характеристики.

Показувати:
- загін/армія;
- командувач;
- склад;
- сила;
- пороги;
- стан;
- маршрут;
- ETA;
- утримання;
- ключові дії.

Швидкі кнопки:
- `Відправити` в Camp;
- `Змінити маршрут` у Movement, якщо дозволено.

## 9. Вікно Army / загону

Відкривається з глобальних меню, замку, області, лицаря.

Показує:
- загін / армія;
- стан;
- область;
- маршрут;
- ETA;
- склад;
- лицарів;
- склад загонів;
- силу;
- Commander-in-Chief;
- пороги;
- утримання;
- доступне переформування.

Кнопки:
- `Відправити` — Camp;
- `Змінити маршрут` — Movement;
- інші — лише якщо дозволені правилами.

Швидкі кнопки руху можна дублювати у списках, але тільки там, де рядок однозначно представляє саме Army/загін.

## 10. Меню «Мітки»

Гравець може поставити на область власну іменовану мітку.

При створенні ім'я необов'язкове. Default: `(q, r)`.

Список:
- назва;
- координати;
- короткий статус області;
- `Перейти`;
- `Перейменувати`;
- `Видалити`;
- `Відправити війська`.

На області:
- поставити;
- редагувати;
- видалити мітку.

## 11. Меню «Обстановка»

Швидкий огляд чужих військ поблизу територій гравця.

Показує чужі Army/загони у релевантній зоні, згруповані за областями/гравцями.

Включає й ті війська, які не породжують окремого оперативного повідомлення.

Іконка може підсвічуватися залежно від близькості/ризику.

## 12. Вікно області

Три вкладки.

### 12.1. «Область»

Показує:
- `(q, r)`;
- власника;
- статус;
- окупацію;
- ресурси;
- джерела;
- місто;
- Neutral Defense;
- інші характеристики області.

Neutral Defense — характеристика області, а не чужі війська.

Потенційні дії:

#### Відправити війська
Доступно в усіх статусах. Кінцева область вже вибрана.

#### Приєднати
Контрольний timer не запускається, якщо область не межує з хоча б однією своєю областю.

При annex обирається замок лише серед тих, для яких виконані всі умови, включно з присутністю в області військ саме цього замку.

Disabled-кнопку можна показати з причиною/таймером, якщо це корисно.

#### Заснувати замок
Доступно:
- у нейтральній області;
- у власній приєднаній області.

Умова:
- Knight без солдатів присутній на старті;
- залишається присутнім і без солдатів увесь час будівництва.

#### Передати область іншому замку
Якщо дозволяє географія і правила.

#### Allow Transit
Елемент керування поточним значенням.

#### Мітка
Поставити / редагувати / видалити.

#### Атакувати Neutral Defense
Тільки з Camp у цій же області.

Якщо підходять кілька Army:
- вибір Army;
- пороги;
- підтвердження.

#### Пограбувати місто
Теж тільки з Camp у цій же області.

Якщо підходять кілька Army:
- вибір;
- пороги;
- підтвердження.

### 12.2. «Свої війська»

Аналог вкладки замку «Армії та загони».

Показує всі свої Army/загони у цій області:
- Camp;
- Movement;
- Regrouping;
- інші локальні стани.

Має повноцінні елементи керування там, де вони дозволені.

### 12.3. «Чужі війська»

Показує доступну гравцю інформацію про чужі Army/загони.

Групування — за гравцями.

Neutral Defense тут не показується.

Якщо ручна атака допустима — кнопка `Атакувати`.

Вікно атаки:
- вибір власної Army;
- пороги;
- підтвердження.

## 13. Відправка військ

Є два входи у flow.

### 13.1. Від Army/загону

Етап 1:
- кінцева область за координатами;
- свій замок;
- мітка;
- Attack Loss Threshold;
- Incidental Loss Threshold;
- Defense Loss Threshold після зупинки;
- checkbox `Використовувати найкоротший маршрут`.

Якщо checkbox активний — другий етап можна пропустити.

### 13.2. Від області

Кінцева область уже відома.

На етапі 1 обирається Army/загін, а також пороги і shortest-route checkbox.

Можна вибрати Army, яка вже рухається.

### 13.3. Етап 2 — route editor

Показати карту з рекомендованим маршрутом.

Гравець може:
- підтвердити;
- додати waypoint;
- змінити waypoint;
- видалити waypoint;
- вручну скоригувати маршрут.

Показувати:
- послідовність областей;
- ETA;
- потенційно конфліктні ділянки;
- чужі території;
- ділянки, де можливий Aggressive Transit;
- кінцеву область.

Гравець не обирає Transit/Aggressive Transit/local goal. Він обирає лише кінцеву точку і маршрут. Локальна мета визначається правилами зі стану кінцевої точки та світу.

### 13.4. Зміна маршруту під час Movement

Якщо Army рухається по A до B, новий маршрут будується від B.

Якщо під час редагування Army вже увійшла в B:
- вихід із B уже зафіксований;
- UI повідомляє, що стартова точка змінилась;
- маршрут перебудовується з наступної області C;
- кінцева точка та пороги по можливості зберігаються;
- весь перший етап повторювати не треба.

Army не зупиняється автоматично лише через затримку користувача в UI.

### 13.5. Army рухається до Camp у поточній області

Гравець може побудувати наступний маршрут заздалегідь.

Поточний рух не переривається.

Після досягнення Camp Army автоматично починає запланований маршрут.

Показати:
`Маршрут заплановано після зупинки`.

## 14. Термінове interaction-вікно при вході чужих військ

Це не toast і не зникає автоматично.

### 14.1. Вхід у нашу область

Після фактичного входу чужої Army, коли локальна мета вже відома, відкривається interaction-popup.

Якщо Transit:
- хто увійшов;
- область;
- напрямок;
- Allow Transit;
- можливість перевірити/змінити Allow Transit, якщо це ще релевантно.

Якщо бойовий контакт:
- атакуюча сторона;
- свої Army в області;
- Camp Army, які беруть участь;
- Transit Army, які ще можна зупинити;
- загальний Defense Loss Threshold = мінімум серед реально залучених захисників;
- окремі пороги;
- `Відступити` біля Camp Army;
- `Зупинити` біля Transit Army;
- `Відступити всім`;
- `Зупинити всі`;
- зміна порогів.

`Відступити` не відкриває вибір області. Це стандартний retreat за правилами системи, аналог retreat після «нульового бою».

Якщо retreat неможливий — кнопка disabled.

### 14.2. Атака Camp у нейтральній області

Показувати аналогічне interaction-вікно оборони, але без нерелевантних елементів.

## 15. Сповіщення

Три канали:

1. Звичайні сповіщення:
   - важливі події;
   - історія;
   - read/unread.

2. Оперативні сповіщення:
   - transient toast;
   - не зберігаються в історії.

3. Оперативні повідомлення / оперативна інформація:
   - поточний актуальний стан;
   - існують, доки актуальні;
   - можуть мати live timer і посилання.

Звичайне сповіщення також показується коротким toast. Клік по такому toast завжди веде на відповідний запис у вікні сповіщень.

Окремий файл описує повні правила генерації.

## 16. Toast behavior

Оперативний toast:
- зникає через кілька секунд;
- не зникає, якщо немає підтвердженої активності користувача;
- якщо toast кілька — зникають по черзі;
- hover на desktop ставить конкретний toast на паузу;
- toast може містити посилання;
- на mobile час показу довший;
- при активності в одній вкладці браузера стан toast синхронізується між усіма вкладками.

## 17. Що Codex може визначити сам

Якщо це не суперечить логіці вище, при реалізації можна самостійно визначити:
- конкретні іконки;
- кольорову палітру;
- typography;
- відступи;
- breakpoints;
- scale-dependent map details;
- точний mobile layout;
- кількість колонок;
- порядок другорядних полів;
- accordion/card/table представлення;
- responsive поведінку.

Пріоритет:
1. не змінювати ігрову логіку;
2. не приховувати критичні дії;
3. не перевантажувати карту;
4. mobile має бути повноцінним.
